# Components

For what Nuxt UI has no equivalent of — built on Nuxt UI's tokens, so a product's palette, a theme's schemes and
dark mode carry through them as they do through Nuxt UI's own components. Inks that carry text use the 700 shade in
light mode and 300 in dark, so they clear 4.5:1 on every Forest scheme (Nuxt UI's 500 does not, on Teal or Slate · Cobalt).

| Component | What it is |
| --- | --- |
| `<ZKicker variant="bracket \| eyebrow">` | The mono label over a section: `[ DEPLOYMENTS ]`, brackets in the primary (default); `eyebrow` is the label itself in the accent ink, no brackets |
| `<ZIdentifier kind="package \| version \| hash \| plain">` | A value set in the mono face, on a chip except `plain`; `version` in the accent |
| `<ZStatus state="healthy \| warn \| suspended \| unreachable \| quiet" pill? glow?>` | Status by **shape** (circle, triangle, square, dashed ring, hollow ring), so it survives grayscale; color only reinforces it. `glow` lights the healthy dot with a soft 12px glow in its own color; the other states stay unlit |
| `<ZSlots :slots="[{ label, available, title? }]" label size?>` | One **named** chip per slot of capacity, as a labeled list: open slots a solid primary badge ("slot 1 · free"), held ones an outline neutral badge saying what holds them ("slot 2 · build 4812"). Nuxt UI's `UBadge` (in the mono face on the theme) |
| `<ZQuotaMeter :used :quota unit warn-at?>` | Usage against a limit: a `meter`, amber from the mark, red and hatched over |
| `<ZCodeBlock variant="inline \| line \| block" code token? lang?>` | The code surface — near-black in both themes — with a copy button; `token` marks the secret. The copy result is announced (`role="status"`), a refused copy says so, and `@copy` fires only on success |
| `<ZTokenReveal token name? require-ack? ack-label? title?>` | The shown-once secret: the token on the code surface (copy, one-click select) under a `[ token · name · shown once ]` kicker, with a warning banner (`UAlert` outline; the default slot is its text). `require-ack` adds a button that blurs the secret and makes it inert; `@copy`, `@ack`, `#actions` |
| `<ZEcosystemMark ecosystem size? with-label? disabled? label? monogram? shape?>` | A package manager as a two-letter mono tile, told apart by **corner shape**, not brand color (npm square, NuGet circle, winget one round corner …); dashed when `disabled`. Named for assistive tech by its label. Six known ecosystems (`components/ecosystems.ts`); any other is drawn from `label`/`monogram`/`shape` (`square`, `circle`, `leaf`, `arch`, `lens`, `drop`, `rounded`) |
| `<ZThemeToggle>` | Light / dark / system as Nuxt UI buttons; `useZooTheme()` is the same over color-mode |
| `<ZRepeatingList v-model item-label :new-row row-key? min? max? errors? compact?>` | A generic (`T`) list editor: rows of the caller's fields in `#row`, Add under them and Remove on each, an optional folded `#summary` with Edit, Done and Cancel that opens on an error, focus into a new row, and the count change announced — [docs](repeating-list.md) |
| `<ZOrderList v-model v-model:selection row-key row-title? title? item-label? max-height? striped? allow-add? allow-remove? removable? confirm-remove? remove-question? remove-description? fill? ui?>` | The list half of a master-detail editor (`T`): a compact listbox with one selected row (selection follows focus, typeahead) and a toolbar of Add, Remove (a `ZConfirmButton`) and four moves; Alt+arrows move by keyboard, moves slide (none under reduced motion) and are announced; `@add`, `@remove` (the list removes the row itself with no listener), `@reorder`, `#item`, `#controls`; `fill` stretches it to its container. Zoo UI's one reorderable list: for picking and ordering beside an editor, where `ZRepeatingList` edits rows in place — [docs](order-list.md) |
| `<ZNumberInput v-model unit? step? min? max? spin? calc? prefix? suffix? min-fraction-digits? max-fraction-digits? freeform? currency? locale?>` | One number input for money, percent, count and hours, formatting as it is typed for the locale: unit marks in fixed slots so a column lines up, its own chevrons and arrow keys moving by `step` from the current value, clamped and rounded on commit, a `calc` mode for `+ - * /`, decimal arithmetic, the caller's string, number or `Decimal` handed back. [Docs](number-input.md) |
| `<ZDateField v-model model-type? min-value? max-value? is-date-unavailable? format? locale? clearable? placeholder? size? icon? calendar-icon? highlight? portal? clear-label? choose-label?>` | A calendar-day field: a `Temporal.PlainDate` or `CalendarDate` v-model, handed back in its own type; typed entry (`5`, `0512`, `5/12/26`, `05122026`), shortcut keys that step from the committed date, a `#leading` slot, a `UPopover` + `UCalendar` picker; Nuxt UI's limit props, with a refused typed date kept out and the field marked invalid; `@date-update` when a date settles, `@invalid`, `@clear`, `@icon-click`, exposed `focus()`. [Docs](date-field.md) |
| `<ZFileDropOverlay accept? multiple? filter? disabled? label? description? icon? target?>` | Files dropped anywhere in the window, not just on a box (Nuxt UI's `UFileUpload`): an overlay that fades in while files are dragged over it (not text or links), counted so children don't make it flicker, hidden on leaving or Escape; `@drop` with the files `accept`, `filter` and `multiple` take, `@rejected` with the rest and why. `target` contains it in one element, a dialog say, drawn inside it; nested overlays defer to the innermost under the pointer, and while one sits in an open modal every overlay outside it stands down. A polite live region announces it; it takes no focus. [Docs](file-drop-overlay.md) |
| `<ZFileList :items remove? locale? remove-label? binary? preview?>` | A form's files, one row each (file-type icon or thumbnail, name, size in 1024s or decimal, Remove, and `#leading`/`#trailing` slots): `File`s and stored `{ id, name, size, type, thumbnail? }` items in one list; `remove` may return a promise, shown as the row's spinner, and a rejection goes to `@remove-error`. [Docs](file-drop-overlay.md#zfilelist) |
| `<ZConfirmDialog cancel-label? confirm-label?>` + `useConfirm()`, `<ZConfirmButton question? description? confirm-label? cancel-label? confirm-color? confirm-variant? question-icon? confirm-enabled? content? arrow? v-model:open>` | Promise-based questions: `confirm()` resolves `true`/`false`, `choose()` the picked action's value or `null`, `confirmDelete()` and `confirmDiscard()` presets; one `alertdialog` host mounted inside `<UApp>`, a second call queued behind the first, focus on Cancel when destructive, a queue per request. `ZConfirmButton` is a `UButton` (every prop passes through) that asks in a `UPopover` and emits `confirm` only on yes, `cancel` otherwise. [Docs](confirm.md) |
| `<ZOptionalDate v-model v-model:enabled? label? disabled? size? clear-when-off? model-type? min-value? max-value? is-date-unavailable?>` | An optional date: a checkbox in front of a `ZDateField`. Off, the field is disabled and the day stays in the model (with `clear-when-off`, the model is `null` and the day comes back on a tick); nothing is written at mount; a tick moves focus into the date; `@enabled-change` on the user's tick or untick; size from the prop, then a `UFieldGroup`, then a `UFormField`. In a `UFormField` the label, help and error belong to the date input; the box is named by `label`. Every other `ZDateField` prop and event passes through; `@date-update` also fires with `null` when unticking takes a day away; exposed `focus()`. [Docs](optional-date.md) |
| `<ZSelectMenu v-model items highlight-selected-on-open? typeahead? close-on-tab? open-on-focus?>` | Nuxt UI's `USelectMenu`, generic (`T`) over its items, with every prop, slot, event and v-model passed through, and the keyboard of a data-entry form: it opens on the selected item; typing on the closed menu picks the first match from the top of the list, a repeated letter cycling (announced, and a surrounding `UForm` told; with `multiple` it opens on the match instead); Tab closes it and moves on, taking the highlighted item in a single-select menu once you have moved the highlight (with `multiple` it leaves the selection); `open-on-focus` opens it on keyboard focus; the focus ring shows on any focus, a click's included. Exposed `triggerRef`, `viewportRef`. [Docs](select-menu.md) |
| `<ZFilterSelect v-model label :options value-key? label-key? count-key? icon-key? icon-class-key? max-shown? show-select-all? icon? searchable? search-placeholder? size? disabled? portal? all-label? clear-label? empty-label? selected-label? announce? ui?>` | A faceted multi-select filter for a toolbar: a button naming up to `max-shown` chosen values as chips (then one "3 selected" chip), opening a `UPopover` + `UListbox` (multiple) of checkbox options with counts and icons (colored per option by `iconClass`), a literal, case-insensitive search with the matches marked, All (`show-select-all`) and Clear; generic (`T`), `ui` classes merged over the defaults, Space and Enter to check, Escape back to the button, the count announced. [Docs](filter-select.md) |
| `<ZSearchInput v-model? debounce? placeholder? icon? clear-icon? clear-label? size? disabled? ui?>` | A search box for a list or table toolbar: a `UInput` (`role=searchbox`, `autocomplete="off"`) with a search icon. What is typed is handed back `debounce` ms (300) after the last key, as `update:modelValue` and `@filter` together; a clear button (shown while there is text, focus kept in the field) and Escape hand back `''` at once; an Escape with nothing to clear reaches the dialog around it; the parent's value is shown without an emit; `ui` merged; everything else passes through to the `UInput`; exposed `focus()`, `clear()`, `inputRef`. [Docs](search-input.md) |
| `useNotify()` + `errorMessage(err, options?)` | Toasts in one line on Nuxt UI's `useToast`: `success`, `info`, `warning`, `error` (alias `danger`) and `primary` `(title?, description?, options?)`, each with its color, icon and close button and 3000 ms; the description may be a caught error; any Nuxt UI toast option passes through; defaults in app.config `zooui.notify`. `errorMessage` reads a `$fetch` error's body (errors list, `detail`, `error`, `message`, `title`) then the error, with a product's own extractor in `zooui.errorMessage`. [Docs](notify.md) |
| `<ZUrlInput v-model v-model:error? add-www? invalid-message? placeholder?>` | A website address field, Nuxt UI's `UInput` (text with `inputmode="url"`): typing writes the text as it is; blur or Enter trims it, puts `https://` in front (in place of `http://`) and checks for a real host with a top-level domain; an address that fails is kept and the field marked invalid through its `UFormField` (`aria-invalid`, the error color) until the next commit, with the message in `v-model:error`; `add-www` (off) adds `www.` to a two-label host; `isWebAddress()` for form rules. [Docs](url-input.md) |
| `<ZMaskedInput v-model v-model:raw? mask? tokens? preset? format-on?>` | A text input with a mask: `#` digit, `A` letter, `*` either, literals between, or a list of masks chosen as typed (by the separator typed, else the first that fits). Only characters the mask takes get in, the caret stays on its character as separators come and go, Backspace and Delete step over them; formatted as typed or on blur (before a `UForm` validates); `null` when empty; exposed `complete`/`isValid`, `commit()`. Presets `phone` (US, on blur, any other number left as typed) and `tax-id` (SSN, or EIN after a dash). [Docs](masked-input.md) |

The colored-edge wrappers (`ZCard`, `ZModal`, `ZSlideover`, `ZDrawer`) are in [Accents and colored edges](accents-and-edges.md#colored-edges). Everything else is Nuxt UI's
own component: `UAlert variant="outline"` is the banner, `UTable` the table, `UTabs` the segmented control.

**Select "none" (`utils/select-none.ts`, auto-imported).** reka-ui, under `USelect` and `USelectMenu`, throws during render
on a `SelectItem` with `value=""`, so an explicit "None" option holds `SELECT_NONE` (`'__none__'`) and is translated back
at the edge: `selectNoneToUndefined(v)` (a create), `selectNoneToNull(v)` (an update that clears the field) and
`emptyToSelectNone(v)` (the value to show for one that may be absent). The names are safe as globals, unlike a bare
`NONE` or `orNull`. Tested by `scripts/select-none.test.mjs`.

**The current-page marker.** On the theme (`@zooui/theme-forest`'s `app.config.ts`; the base leaves `UNavigationMenu` as
Nuxt UI ships it), where a `UNavigationMenu` asks for Nuxt UI's `highlight`, the bar's thickness and the current
item's weight read `--nav-highlight-size` and `--nav-current-weight`. A product sets them in its own CSS (say `2px` and
`700`); unset, they fall back to exactly what Nuxt UI ships (1px, medium), so no menu changes until it does.
`variant="link" color="neutral" highlight highlight-color="primary"` gives no pill, the current page a neutral label
over a primary underline (`highlight-color` must be named: unset, Nuxt UI takes it from `color`, and the bar goes
neutral).
